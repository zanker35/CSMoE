# Master + CSO UI：运行与验收记录

当前分支：`feat/260930-minimal`。界面移植基线是 `master f1da796`，
界面来源是 `citrus acb25d3`。

当前内容范围：人物截至 2009 年；武器截至 2010-06-09（含），无圣诞版、
CS:GO 武器和 Z4B 扩展。共 18 个可选人物、44 项购买目录，详情见
[当前内容范围](content-scope.md)。

模式只保留竞技、个人竞技、团队竞技、生化Ⅰ、生化Ⅱ。
[模式清理与验证范围](content-scope.md#模式)。

## 打开就玩

双击仓库里的 **`tools/CSMoE-CSO-UI.command`**，或运行：

```sh
./tools/run-cso-ui.sh
```

进入“创建游戏”，默认地图 `de_dust2`，点击“开始”，再选择阵营和人物。
首次配置为 8 人房、4 个简单 BOT、16,000 起始金钱、9 分钟购买时间，
可以在创建游戏页面自行调整。启动器不会覆盖已经保存的个人设置。

- `B`：购买；`M`：选择阵营；`Tab`：记分板；`Esc`：菜单。
- 购买页面里的 S / D / F / G / H 是五组预设，分别以 MP5、AWP、MG3、
  M14 EBR、M134 为主武器，并搭配副武器、刀、手雷和护甲。
  已保存的预设优先，主动清空的预设也会保留。

新程序在 `build-cso-ui/game_launch/CSMoE.app`，同时已同步到 `dist/CSMoE.app`。
使用上述启动器提供资源路径和隔离的配置目录。

## 移植内容

- CSO 风格主菜单、创建游戏、模式／地图／BOT／游戏规则设置、
  服务器地址连接、选项页面与控制台。
- 阵营选择、18 个人物（CT 10 个、T 8 个）、头像、介绍和翻页。
- 购买分类、武器预览与价格、重购、五组本地预设。
- CSO 风格血量、护甲、弹药、金钱、雷达、回合比分／计时、角色头像、
  击杀信息、胜利横幅和拾取提示。
- 当前编译 52 个武器 CPP，购买目录 44 项；模式只保留上述五种。
  武器 CPP 数包含生化补给武器、另一形态、C4 和僵尸爪。

为了让这些页面真正接上 master，还修正了 VGUI／引擎 ABI、中文加载顺序、
加载窗口不释放、HUD 文字裁剪、人物编号与服务端映射、消息协议、
部分武器资源路径、扩展 `.seq` 动作加载，以及生化模式未选角玩家参与感染
造成的空武器崩溃。

macOS 上还修正了开服时主线程等待本机域名解析的问题，以及在半透明游戏菜单
后面错误绘制自己的第一人称身体的问题。窗口与 drawable 尺寸分开处理，
交付默认仍使用 `vid_highdpi 0`；物理 2 倍 Retina 模式未纳入最终实测。

## 移植阶段的历史验证（本轮精简验证见上方记录）

测试机器为当前 Apple Silicon Mac，使用本机已有资源包。

- 从真实创建游戏按钮开服；修改 BOT 数量、输入中文房间名，
  正在运行的房间从 8 人改为 10 人后重新进入。
- 真实阵营／人物按钮、上一页／下一页、选定人物后出生。
- 真实购买分类、M4A1 预览与购买，金钱从 16,000 减到 12,900，
  手中实际出现 M4A1。
- 经典模式本地玩家 + 4 BOT、M4A1 与 Gungnir、开火、武器实体、
  资源预缓存、记分板与购买页面截图、正常退出。
- ZB2 下先不选角色，3 个 BOT 连续感染／结束回合仍正常；
  没有 BOT 时等待后再选角色、增加 BOT，也能开始感染。
  日志确认 BOT 和本地玩家获得 `knife_zombi`，并完成多次回合切换。
- 视频页面真实点击“应用”：1280×800 → 1440×900 → 1280×800；
  世界、HUD 和菜单完整显示，菜单中不再出现自身模型穿屏。
- 共享接口尺寸／偏移检查；真实 HUD 消息消费者的 ASan 回归，
  包括 11 个 TextMsg、4 个 TeamScore、24 个 Brass 生产者／消费者组合，
  损坏消息仍保留诊断。
- 角色索引／路径检查，`.seq` 加载器的 46 组实际模型与损坏输入检查；
  普通僵尸和 Deimos2 的蹲走／蹲停动作引用检查。

构建与回归入口：

```sh
./tools/build-cso-ui.sh
node tools/check-cso-hud-messages.js
./tools/run-cso-ui.sh --check
./tools/run-cso-ui.sh --smoke-quit
```

`--smoke-quit` 等待实际客户端 signon 与 `Local` 状态，再测试 BOT 和武器，
不是只等待一段时间就宣告启动成功。它还测试导航文件尺寸，但会归档探测时
生成的导航文件并恢复原来的覆盖状态，不替换日常游戏使用的导航数据。
真实渲染仍需看截图，鼠标行为需另做界面回归；详见 `tools/cso-smoke/README.md`。

只有显式传入 `-uitest` 才注册 `ui_test_tree/click/type/hover/command`，
这些工具通过游戏自己的 VGUI 输入与消息分发检查真实控件。

构建日志：`build-cso-ui/full-build.log`。
运行日志：`build-cso-ui/run/logs/`。
实际截图：`build-cso-ui/run/csmoe/scrshots/`。

## 数据与边界

所有新配置、日志和截图写入 `build-cso-ui/run`。`dist` 通过 Xash 的只读
搜索路径挂载。后续 MVP 清理已更新本地应用和资源包；连接 Steam 的
`cstrike`／`valve` 符号链接保留。构建产物和游戏素材不进入源码提交。
当前实施范围及资源清理命令见 [MVP 清理记录](mvp-cleanup.md)。

这次交付是可以本地游玩的 master 界面移植，不是新版 citrus 完整玩法的重造：

- master 没有服务端实现的新模式不显示为可用；账号登录和公网服务器目录
  没有后端，不声称可用。地址连接入口已接通，但没有进行外网多人实测。
- 后期人物及 buff-class 定义已删除。资源包仍有少量非致命声音／占位
  图片缺失；部分 `.sc` 名称由原生代码注册，并不需要同名外部文件。
- 没有 HTML 浏览器后端，欢迎页使用原生文本，其他 HTML 控件安全禁用。
  引擎不支持的喷图与声音质量选项显示为默认值，不发送无效设置命令。
- 已验证核心路径，不代表每把枪的全部技能、全部模式或所有操作系统都经过测试。
  引擎仍会打印部分旧碰撞／资源警告，没有通过屏蔽日志伪装成零问题。

模型、地图、音频和图片是外部本地资源。导入源码保留原有许可证与作者声明。
